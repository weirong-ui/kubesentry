# 预注册：D2a 重复实验协议（KubeStasis vs HPA）

> **状态：已锁定（预注册）**。本文写于任何 D2a 数据采集之前，提交哈希即锁定凭证。
> 首轮数据落盘之后，本文只允许在 §11 修订记录**追加**，§1–§10 的判定线一个字不许改。
> 要改 = 重新预注册，git 历史可查。

**为什么要有这份文件**：主报告 [hpa-vs-kubestasis.md](hpa-vs-kubestasis.md) 是单次运行；
[variance-precheck.md](variance-precheck.md) 已复算证明它最想讲的"快"与 HPA 侧自身噪声同量级（σ≈8s）。
重测会给出 10 轮数据——如果判定规则不提前写死，事后挑口径、挑指标、挑轮次的诱惑会一直存在
（p-hacking 的三个入口）。所以先把"什么算赢、什么算没赢、废数据谁说了算"全部入库。

## 1. 锁定的身份与环境

| 项 | 值 |
|---|---|
| KubeStasis 行为版本 | 含 `scaleDownStabilizationSeconds`（默认 60s，`1301365`）的 main。每轮开始时记录 controller 镜像 digest + git commit；与锁定值不符 → 该轮判废 |
| HPA 行为版本 | 全默认（CPU 50% 目标、300s 缩容稳定窗口、1..5 副本），不调参 |
| 负载镜像 | `kubestasis-demoapp:v1-bench`，CPU_SPIN_MS=8，requests 250m / limits 500m，QPS 目标口径同主报告 §1（16 QPS/Pod） |
| 流量时间线 | 与主报告完全一致：0–120 基线 12 QPS；120–360 突发#1 +150；360–480 空闲#1；480–600 突发#2 +150；600–1140 空闲#2。挂钟驱动，总长 1140s |
| 集群 | docker-desktop 单节点 v1.36.1，metrics-server + Prometheus 各一份 |
| 串行运行 | **每轮只部署一臂**（另一臂的 Deployment/HPA/App/loadgen 不存在），单臂独占节点 CPU。这消除了 precheck 指出的组间 CPU 争抢污染，代价是绝对数字与 run5（双组同跑）不可比——D2a 结果自成一体，不与 run5 直接比数 |

**loadgen 保底 CPU**：loadgen Deployment 补 `resources.requests`（run5 实测 loadgen 启动延迟 ~48s，是单节点调度饿死的直接产物）。

**清场**：每轮开始前删除整个 bench 命名空间并重部署——全新 CR 对象，迟滞/冷却/稳定窗口状态归零。

## 2. 假设与指标

**H1（主假设，确证性）**：空闲期收缩使 KubeStasis 的副本-分钟低于 HPA。

| 级别 | 指标 | 口径 |
|---|---|---|
| **主指标（确证性）** | 副本-分钟 | 阶梯积分 Σ replicas×采样间隔 / 60，与 `benchmark_report.py` 的 `replica_seconds` 完全同口径 |
| 次指标（描述性） | 扩容响应（突发#1 首 >1）、到峰值用时、空闲后回 1 副本用时、副本变更次数、loadgen 失败请求数 | 全部沿用 v1 口径，只在轮末从 loadgen 日志抓取失败数 |
| 计数指标 | 误缩容 | 定义写死：突发#2 窗口 [480,600] 内 `replicas` 相邻采样出现下降，计 1 次（连续多步各计 1 次）。HPA 侧预期恒 0 |

次指标**不构成统计检验**：只报 5 轮中位数、极差、方向计数。理由先写死——多指标各做检验就是多重比较，挑通过的说就是挑口径。

## 3. 设计：串行 + ABBA 配对交替 × 5

10 轮，5 个配对，对内顺序交替（防笔记本时间漂移——电池、温控、后台任务随时间变化，ABBA 让两臂在时间轴上对称采样）：

| 配对 | 第 1 轮 | 第 2 轮 |
|---|---|---|
| 1 | HPA | KubeStasis |
| 2 | KubeStasis | HPA |
| 3 | HPA | KubeStasis |
| 4 | KubeStasis | HPA |
| 5 | HPA | KubeStasis |

配对差定义：`d_i = 副本分钟_KS − 副本分钟_HPA`（对 i 的两轮，i = 1..5）。

**备用轮**：每臂最多补 2 个备用位（追加在同臂末尾，配对关系不变）。总判废超过 4 轮 → 停止实验，如实报告环境不稳。

## 4. 判定线（写死，结果出来前入库）

对 5 个配对差 d_i 做单侧精确符号检验：

| 结果 | 判定 | 预注册措辞 |
|---|---|---|
| 5/5 个 d_i < 0 | **支持 H1**（p = 0.031） | "在预注册协议口径内，副本-分钟差异经 5 次独立配对重复确证" |
| 4/5 个 d_i < 0 | 方向一致、证据不足（p = 0.188） | "方向与预注册假设一致，但未达判定线"——**不许**用"确认""证明" |
| ≤3/5 | 未检出 | "未检出副本-分钟差异；不等于证明无差异" |

- 配对差均值、每臂 σ（n=5）只作描述性报告，不做检验、不做"Xσ"表述。n=5 的 σ 自身置信区间仍然很宽（自由度 4 时 95% CI 约横跨 0.6σ–2.9σ），precheck §1 的声明同样适用于此。
- **不删任何机器判 VALID 的轮**。删轮的权力只属于 §6 的机器判废规则，不属于人。

## 5. 分析流程与脚本验收（方案 B：适配层）

1. `benchmark.sh` 改单臂模式（`--arm hpa|ks`），输出长表 CSV：`run_id, arm, ts, phase, replicas, desired, cpu_m, qps`（+ 轮末一次性 failures）。
2. 新分析脚本从长表算本文 §2 的全部指标 + §6 的判废结论（每轮输出 `VALID/INVALID + 原因`）。
3. **宽表→长表适配层验收**：新分析脚本须能读旧的宽表 `data.csv`（`hpa_current`/`ks_ready` 等列）重算 v1 的 8 项指标，与现版 `benchmark_report.py` 输出**逐项一致**。这是"丢旧脚本不伤可复算承诺"的验收线——先过这条，再跑任何 D2a 轮。
4. 统计部分只做一件事：§4 的符号检验。没有第二个检验，没有事后变量转换，没有剔除规则以外的数据操作。

## 6. 判废规则（机器判，人不能推翻）

每一条对应历史上一轮真实废掉的原因，全部由分析脚本自动判定：

| # | 规则 | 来源教训 |
|---|---|---|
| 1 | 相邻采样间隔中位数 > 7s，或 >10% 的间隔 > 10s（时间轴拉伸） | run2 前的循环计数器 bug |
| 2 | 任一突发窗口内该臂 QPS 连续 > 60s 为 0（信号失明） | run3 Prometheus CrashLoop |
| 3 | 突发窗口内副本峰值 < 5（超卖失明） | run2 KS 单副本饱和 |
| 4 | t < 120 时副本数 > 1（上一轮没清干净，基线污染） | 清场不彻底的一般风险 |
| 5 | QPS 首次超过 100 的时刻距突发起点 > 60s（loadgen 启动异常；串行+保底 CPU 后不应再出现，出现即环境异常） | run5 的 48s 启动延迟 |
| 6 | 采样期间 Prometheus 或 metrics-server 不可用 | run3 |

## 7. 结果怎么写（三种结局的措辞，现在就定）

- **H1 站住**：主报告顶部声明"副本-分钟结论已被预注册重复实验确证"，其余结论维持现状（单次观察口径）。
- **H1 未达线**：主报告的"副本-分钟 -12.5%"降级为"单次运行观察，预注册重复未能确证"，**整份报告的一句话结论改写**，不是加个脚注。
- **实验中止**（判废 > 4 或 §10 超时）：报告已完成轮数的描述统计，明确写"未完成预注册协议"，不从中提取任何方向性结论。

## 8. 口径边界（从主报告 §4 全文继承，不因重测而放宽）

单节点、纯忙等负载、信号不同型是设计差异、HPA 全默认、KS 参数全默认、副本-分钟不含变更成本。重测解决的是"单次运行、无方差"这一条，**不解决其余六条**。串行运行额外引入的新边界：两臂不同时承受负载，绝对吞吐环境与双组同跑不可比。

## 9. 后置项：KEDA 臂（D2b）与稳定窗口臂（G3）

- **D2b 后置的理由是"先重复、再对照"，不是回避**：D2a 若连 H1 都没站住，KEDA 臂没有对象；若站住，KEDA 臂定位为**解释性验证**——同为 QPS 信号，预期与 KubeStasis 持平；若真持平，恰好证明"扩容响应优势属于信号类型而非实现"。KEDA 臂不进本协议任何判定线，不做胜负宣告。
- **G3（关稳定窗口 vs 默认 60s）降为二阶**：仅当 D2a 的 5 个 KS 轮中误缩容 ≥ 2 次时立项（触发后写入 ROADMAP）。0–1 次则视为已修复，不再花实验预算。

## 10. 时间与止损

- **硬上限：自首轮数据采集起 3 个自然日**。超限即停，按 §7 第三条措辞收尾。
